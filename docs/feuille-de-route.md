## 2. Règles de découpage adoptées

1. **Un commit ne porte qu'un seul motif de changement de résultats** (ADR 0007 : une seule branche de travail, un commit par issue qui change un résultat). Un commit qui change des valeurs (σ_USP, p-value, verdict) ne contient aucun refactor ; le refactor fait l'objet d'un commit distinct dont le critère d'acceptation est « références strictement identiques ». Corollaire : le commit de refactor n'a pas de tableau avant / après, et c'est ce qui le protège.
2. **Un changement de structure sans changement de valeur** (champ ajouté, ligne de test ajoutée) régénère les références, mais son tableau avant / après ne doit contenir que des lignes « absent / ajouté » ; toute ligne de valeur modifiée est une régression. Depuis l'amendement de l'ADR 0006, un changement qui ne pose **aucune valeur numérique finie** (chaînes, `NA`, booléens, suppressions) passe par le **patch chirurgical** (`tests/patcher_reference.R`), autorisé depuis une session cloud ; tout changement numérique reste une régénération sur la plateforme désignée (poste du mainteneur), avec visa.
3. **Régénérations et patchs à valeurs modifiées** — le seul coût réel, car chaque ligne du tableau doit être expliquée et approuvée. **Faits** : J1a (deux verdicts OK → INFO par méthode lognormale, 44 grandeurs non numériques, patch chirurgical, PR #17) ; J3 (σ_USP réserve n° 2 +6,92 %, régénération de `reserve2.rds`, PR #15) ; D(5)(d)(ii) (trois chaînes dont un verdict OK → INFO sur `reserve2`, patch chirurgical, PR #18). **À venir**, dans l'ordre des branches : B — #19 (σ_USP change pour six segments hors des cas de test ; **aucune référence ne bouge**, le tableau porte sur les segments touchés), #39 (patch chirurgical : deux `detail`, deux `H0`, un `type`) ; **aucune régénération dans B**. C — #24 (huit verdicts → INFO par méthode lognormale, `sens_du_test` → `NA` pour les non-tests, grandeurs non numériques : patch chirurgical, visa du mainteneur, M7) ; #29 (`Runs` 1,000 → 0,743 et `Runsr` 0,768 → 0,743, `nature_p` de `Runsr` → « exacte », verdicts inchangés : **régénération** de `premium.rds` et `reserve1.rds` sur le poste, tableau validé par `actuary`, M8) ; #22 (grandeur numérique ajoutée, deux lignes éventuellement déplacées : régénération structurelle des deux mêmes fichiers). D — #40 (`err_mc` des statistiques bilatérales : **régénération des trois `.rds`** sur le poste, aucune p-value ni verdict, tableau validé par `actuary`) ; #37 (champ de `$metadata` : patch chirurgical). E — #44 (verdicts et `nature_p`, méthodes lognormales), #46 (p_mc et IC bootstrap Merz-Wüthrich), #47 (lignes graphiques), #45 (ajouts) ; #43 seulement si le préalable révèle une divergence. Aucun autre jalon ne doit modifier une valeur existante. **Ordre des régénérations** : toutes après le commit #14-1 (tête de B), de sorte que chaque fichier régénéré sur le poste soit contrôlé par la CI au critère de M9 ; les régénérations de C (#29 puis #22) et de D (#40) portent chacune un motif unique et se succèdent sur les mêmes fichiers sans se gêner, une régénération réécrivant tout le fichier avec les valeurs du poste.
4. **Fichiers de référence séparés** : `premium.rds` et `reserve1.rds` ne bougent que pour les jalons lognormaux, `reserve2.rds` que pour les jalons Merz-Wüthrich. `Rscript tests/generer_references.R <cas>` ne régénère que le cas concerné ; le message de commit nomme la plateforme (ADR 0006 point 5) ou, pour un patch, les motifs et les comptes de grandeurs patchées et laissées.
