Finalité qui ordonne tout : un dossier soumis à l'ACPR, où le relecteur doit pouvoir suivre chaque résultat de la formule réglementaire au code, du code à la documentation, et de la documentation aux tests. Un chantier est **indispensable à la remise** s'il corrige un écart au règlement, un résultat faux, ou une affirmation fausse de la documentation sur ce que fait le code. Tout le reste est de la qualité de forme : utile, mais différable.

**Vocabulaire depuis l'ADR 0007.** Un *jalon* (J0, J1a…) est un ensemble cohérent de travaux ; il se réalise désormais par un ou plusieurs commits d'une **branche de travail unique** au périmètre fermé d'issues (trois à cinq, plafond indicatif), avec une PR ouverte en brouillon dès la création de la branche, un commit par issue qui change un résultat (σ_USP, p-value, verdict), et un tableau avant / après par commit de ce type. Les branches de travail sont nommées ici par une lettre (A, B, C, D) ; la lettre D désignait, dans la première version, la piste documentaire : elle est renommée **PD** ci-dessous pour lever l'homonymie.

## 2. Règles de découpage adoptées

1. **Un commit ne porte qu'un seul motif de changement de résultats** (ADR 0007 : une seule branche de travail, un commit par issue qui change un résultat). Un commit qui change des valeurs (σ_USP, p-value, verdict) ne contient aucun refactor ; le refactor fait l'objet d'un commit distinct dont le critère d'acceptation est « références strictement identiques ». Corollaire : le commit de refactor n'a pas de tableau avant / après, et c'est ce qui le protège.
2. **Un changement de structure sans changement de valeur** (champ ajouté, ligne de test ajoutée) régénère les références, mais son tableau avant / après ne doit contenir que des lignes « absent / ajouté » ; toute ligne de valeur modifiée est une régression. Depuis l'amendement de l'ADR 0006, un changement qui ne pose **aucune valeur numérique finie** (chaînes, `NA`, booléens, suppressions) passe par le **patch chirurgical** (`tests/patcher_reference.R`), autorisé depuis une session cloud ; tout changement numérique reste une régénération sur la plateforme désignée (poste du mainteneur), avec visa.
3. **Régénérations et patchs à valeurs modifiées** — le seul coût réel, car chaque ligne du tableau doit être expliquée et approuvée. **Faits** : J1a (deux verdicts OK → INFO par méthode lognormale, 44 grandeurs non numériques, patch chirurgical, PR #17) ; J3 (σ_USP réserve n° 2 +6,92 %, régénération de `reserve2.rds`, PR #15) ; D(5)(d)(ii) (trois chaînes dont un verdict OK → INFO sur `reserve2`, patch chirurgical, PR #18). **À venir** : #19 (σ_USP change pour six segments hors des cas de test ; **aucune référence ne bouge**, le tableau porte sur les segments touchés) ; #24 (jusqu'à huit verdicts → INFO, grandeurs non numériques : patch chirurgical probable, visa du mainteneur) ; #29 (si `p_ex` est accordée à `Runsr`, `p_retenue` numérique change : régénération de `premium.rds` et `reserve1.rds`) ; #22 (grandeur numérique ajoutée : régénération structurelle) ; J4 (verdicts et `nature_p`, méthodes lognormales) ; J6 (p_mc et IC bootstrap Merz-Wüthrich) ; J0 seulement si le préalable révèle une divergence. #39 (quatre points : deux `detail`, deux `H0`, un `type`) et #37 (champ de `$metadata`) : patch chirurgical de textes seuls. Aucun autre jalon ne doit modifier une valeur existante.
4. **Fichiers de référence séparés** : `premium.rds` et `reserve1.rds` ne bougent que pour les jalons lognormaux, `reserve2.rds` que pour les jalons Merz-Wüthrich. `Rscript tests/generer_references.R <cas>` ne régénère que le cas concerné ; le message de commit nomme la plateforme (ADR 0006 point 5) ou, pour un patch, les motifs et les comptes de grandeurs patchées et laissées.
5. **Un ADR par décision de forme** avant le code : ADR 0003 (catalogue Monte-Carlo, J1b) et ADR 0004 (graine locale, J2a), acceptés ; ADR 0005 (MSEP D(5) lue sur pièce, M1 close sans objet) et son amendement (pagination L 12/277-278 vérifiée pour la version d'origine) ; ADR 0006 (plateforme des références) et son amendement (patch chirurgical) ; ADR 0007 (une branche de travail à la fois) ; ADR 0008 (PDF compilé aussi en session cloud). À venir : l'ADR de mise en œuvre de la bascule CI (J10), qui remplacera le point 1 de l'ADR 0006 ; un ADR si M7 restreint ou amende l'ADR 0001.
6. **`docwriter` passe après `coder` sur une même branche**, jamais en parallèle ; le PDF est recompilé et commité avec chaque commit du `.tex`, dans tout environnement, la chaîne nommée (ADR 0008).
7. **Un problème hors périmètre devient une issue, sur accord du mainteneur** (ADR 0007 points 3 et 4) ; seule exception, le correctif rapide (références identiques, un seul domaine de commit, pas de `.tex`), par branche temporaire et PR directe vers `main`, puis `main` fusionnée dans la branche de travail.
