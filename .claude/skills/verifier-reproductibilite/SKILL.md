# Vérifier la reproductibilité

Toute différence de résultat doit être **identifiée, quantifiée et expliquée** (`docs/exigences.md`, § 4.5). Cette procédure produit cette traçabilité, dans le même format à chaque fois.

Commandes depuis la racine du dépôt. `Rscript` est dans le PATH grâce au hook de session ; à défaut, sous Windows : `"/c/Program Files/R/R-4.3.1/bin/Rscript.exe"`.

## Étapes

1. **Lancer les tests** : `Rscript tests/test_reproductibilite.R` (~2 min).
   - Code de sortie 0 → terminé : rapporte « reproductibilité et non-régression vérifiées » avec les σ_USP affichés.
   - Échec « deux appels à graine identique diffèrent » → **défaut bloquant** : une source d'aléa sans graine ou un état global a été introduit. Le trouver et le corriger ; ne jamais régénérer les références dans ce cas.
   - Échec « écart à la référence » → étape 2.

2. **Produire le tableau avant / après** : `Rscript tests/comparer_references.R [cas]`. Il applique le critère de non-régression (`comparer_objets()`, `tests/outils_tests.R` : 1e-6 par valeur, en relatif, ou en absolu pour une référence quasi nulle ; ADR 0006, second amendement). Il liste chaque grandeur **en écart au seuil**, avec sa valeur de référence, sa nouvelle valeur et l'écart, et affiche une ligne de synthèse par fichier (nombre de feuilles non strictement identiques, écart maximal et feuille qui l'atteint). La dérive de plateforme sous le seuil n'est pas listée ; `--seuil 0` liste toutes les feuilles non strictement identiques, par exemple pour documenter un changement plus fin que 1e-6.

3. **Expliquer chaque ligne** du tableau par la modification effectuée. Toutes les lignes doivent être expliquées :
   - écart attendu et expliqué → étape 4 ;
   - écart inattendu ou inexplicable → c'est une régression : corriger le code et reprendre à l'étape 1.

4. **Faire produire les références par la CI**, seulement quand chaque écart est expliqué. **Aucune régénération ni création de référence hors de la CI**, poste du mainteneur compris (`docs/adr/0011-…`, point 10) : `Rscript tests/generer_references.R` en local n'a plus d'usage légitime que l'expérimentation sur un arbre non commité. Deux voies, plus la création d'un cas nouveau :
   - **Changement purement non numérique** (chaînes, booléens, `NA`, suppression d'une entrée) : patch chirurgical, `Rscript tests/patcher_reference.R` (premier amendement de l'ADR 0006), possible depuis toute session ; puis relancer l'étape 1 jusqu'au vert.
   - **Toute autre régénération** : mode `regeneration` du workflow `.github/workflows/references.yml` (un ou plusieurs cas, M33 ; `tests/regenerer_et_rendre_compte.R <cas1> --attendu <motif> … [<cas2> --attendu <motif> …] --issue NN --ecrire`, chaque cas suivi de ses propres motifs, qui refuse toute feuille modifiée hors des motifs attendus de son cas). **Tous les cas dont le commit de code change la référence sont régénérés dans une seule exécution** (#40 : les quatre cas `premium`, `reserve1`, `reserve2`, `premium_ii6`) : chaque cas est recalculé et vérifié à son tour, tout ou rien (un cas refusé, aucune référence écrite ni publiée), un tableau avant / après par cas, puis les deux batteries relancées **une seule fois**, après le dernier cas ; régénérer un cas seul laisserait les autres en écart et la batterie refuserait. Entrées du workflow : `cas` = noms séparés par « , » (`premium, reserve1, reserve2, premium_ii6`), `attendu` = un jeu de motifs par cas, dans l'ordre de `cas`, jeux séparés par « ;; », motifs d'un jeu séparés par « ; » (`m1 ; m2 ;; m3 ;; …`) ; un cas seul s'écrit comme avant (`cas = premium`, `attendu = m1 ; m2`). L'essai à blanc local, sans `--ecrire`, n'écrit rien et aide à fixer les motifs ; mais, calculé hors CI, il peut signaler une dérive de plateforme sans rapport avec la modification (relevé par `audit` : 1,6e-16 sur `plots_data$surface$objectif[1771]`) : les motifs attendus fixés localement ne valent pas pour la CI, dont le tableau fait foi. La procédure est celle de l'en-tête du workflow et du point 3 de l'ADR 0011 (rôles M29) :
     1. **déclencher** (session principale, **sur ordre explicite du mainteneur**) sur une **branche éphémère** (M30, ADR 0011 amendé le 24/09/2026), jamais sur `main` ni sur la branche de travail : depuis la tête de la branche de travail (notée `<tête W>`), `git switch -c claude/regeneration-<issue>`, y faire le commit de code de l'issue (R/, tests/ hors `tests/reference/`), **non poussé sur la branche de travail**, puis `git push -u origin claude/regeneration-<issue>` (aucune PR, jamais fusionnée) ; déclencher par l'API GitHub (`workflow_dispatch`) avec `ref = claude/regeneration-<issue>`, `mode = regeneration`, le ou les cas, un jeu de motifs attendus par cas et l'issue ; noter l'identifiant de l'exécution et le commit calculé (en tête du résumé du job) ;
     2. **lire le tableau** avant / après de l'exécution (résumé du job) ; en cas de refus, rien à commiter sur la branche de travail : la correction devient un **commit supplémentaire sur la branche éphémère** (poussé ; sa tête est le nouveau commit calculé), puis nouvelle exécution ; corriger à la source, **jamais** en relevant `TOLERANCE` ni en ajoutant une feuille à `INSTABLES` ;
     3. **visa** : le mainteneur vise le tableau réel de cette exécution (tout changement de σ_USP ou de verdict) ou `actuary` (fiche `actuary-approfondi`, `docs/agents/routage.md` § 3) valide les p-values sans verdict (règle de `CLAUDE.md`) ; sans visa, rien n'est commité ;
     4. **télécharger** l'artefact « references-… » de cette exécution (en session cloud, le domaine `*.blob.core.windows.net` doit être autorisé ; à défaut le mainteneur dépose l'artefact, ADR 0011 point 9) ;
     5. **vérifier** : (a′) le commit calculé (`plateforme.txt`) est la tête de la branche éphémère ; sur la branche de travail (`git switch <branche de travail>`), `git cherry-pick -n <tête W>..<commit calculé>` (l'intervalle reprend tous les commits de la branche éphémère ; quand elle en porte deux, `cherry-pick -n <commit calculé>` seul échoue en conflit, ou n'applique que la tête sans le signaler, arrêté alors par (a′)), copier les `.rds` de l'artefact (un par cas régénéré) dans `tests/reference/` et les `git add`, puis vérifier sur l'**index** : `git diff --cached --quiet <commit calculé> -- R tests ':(exclude)tests/reference'` doit rendre 0 (index = code du commit calculé), et `git diff --quiet -- R tests` rend 0 (arbre de travail = index : (c) teste l'arbre de travail, et une modification non indexée passerait la vérification sur l'index) ; consigner l'empreinte `git rev-parse <commit calculé>:R`. Si la branche de travail a reçu, pendant la vie de la branche éphémère, un commit touchant `R/` ou `tests/` (hors `tests/reference/`), (a′) refuse, et ne se contourne pas : supprimer la branche éphémère, la recréer depuis la nouvelle tête de la branche de travail en y reportant le commit de code et ses correctifs, et relancer le workflow ; l'artefact de la première branche est abandonné et son exécution devient une **exécution non retenue**, citée dans le message du commit final (point 6). Un commit de la branche de travail qui ne touche ni `R/` ni `tests/` (`.tex`, `docs/`, `.claude/`, `.github/`) ne provoque pas ce refus ; (b) les md5 de **tous** les `.rds` copiés sont ceux de `md5.txt` (md5 de l'artefact contre `md5.txt` du même artefact : c'est le seul rapprochement de md5 valable ; le md5 d'un `.rds` écrit sur un poste dépend de la locale de la session R, chaînes enregistrées avec leur marque d'encodage, et ne se compare jamais à celui d'un `.rds` de la CI — #83, ADR 0011 annoté ; les valeurs se comparent par `comparer_objets()`, en (c)) ; (c) `Rscript tests/comparer_references.R --deux-parts` sur les `.rds` copiés (part non numérique vide, seule la dérive entre la machine de la session et la CI apparaît), puis `Rscript tests/test_reproductibilite.R` ;
     6. **commiter** code et `.rds` en **un seul commit nouveau** sur la branche de travail (`git commit` de l'index vérifié en (a′), domaine du code ; jamais `--amend` ni fixup, ADR 0007 point 6), dont le message reprend le tableau avant / après (ou son emplacement `docs/tableaux/…`), la plateforme (ImageOS, ImageVersion, R, BLAS), l'écart maximal par fichier, le lien de la **dernière** exécution, le SHA de la **tête** calculée, après une reprise une ligne citant les exécutions refusées (lien, cause du refus), et une ligne citant les exécutions non retenues (lien, motif : branche de travail avancée, branche éphémère recréée), l'empreinte `git rev-parse <commit calculé>:R` (identique à `git rev-parse HEAD:R` après le commit), les md5 et le visa ; supprimer **aussitôt** la branche éphémère (`git push origin --delete claude/regeneration-<issue>` et `git branch -D claude/regeneration-<issue>` ; en session cloud, où le proxy git coupe la suppression d'une branche distante, supprimer la branche locale et demander au mainteneur de supprimer la branche distante) ; pousser sur la branche de travail sur ordre du mainteneur, puis vérifier que la CI est verte.

   - **Création d'un cas nouveau** (M31, ADR 0011 amendé ; par ex. #61 `premium_ii6`, #55 `premium_net`) : mode `creation` du même workflow (`tests/regenerer_et_rendre_compte.R <cas> --creer --issue NN --ecrire`), pour un cas ajouté à `CAS` de `tests/outils_tests.R` qui n'a pas encore de `.rds`. Le workflow valide l'entrée `cas` (texte libre : `^[a-z][a-z0-9_]*$`, présence dans `CAS` du commit calculé), **refuse si `tests/reference/<cas>.rds` existe**, écrit le fichier, vérifie que **les md5 des `.rds` existants n'ont pas changé** et que `git status` sous `tests/reference/` ne montre que le fichier ajouté, relance les deux batteries (`test_reproductibilite.R` couvre alors le nouveau cas) et publie le même artefact. Tableau de non-régression « absent / ajouté » seulement ; une comparaison du nouveau cas à un cas existant, si elle est demandée, est produite à part. Procédure : celle des points 1 à 6 ci-dessus, la branche éphémère portant le commit qui ajoute le cas à `CAS` (et, s'il y a lieu, le code de l'issue), avec `mode = creation`, le cas et l'issue ; en (b) et (c), `<cas>.rds` est un fichier ajouté.

   La **bascule** est le mode de tout changement de plateforme de calcul (ADR 0011 amendé, M34) : elle porte sur **tous les cas de `CAS`**, se déclenche sur la branche de travail (sans branche éphémère ni code à commiter) et s'éprouve en **deux exécutions successives** A puis B sur la même tête : les `.rds` ne sont commités (ceux de A, `.rds` seuls dans un commit `tests:`) que si les `md5.txt` de A et de B sont identiques, avec le visa prévu par l'ADR ; sinon rien n'est commité et le mainteneur est saisi avec la mesure de l'écart (en-tête de `references.yml`).

5. **Rendre compte** : le tableau avant / après, l'explication de chaque écart, et le résultat final des tests. Ce compte rendu va dans le message de commit ou la description de la PR ; les références d'une régénération produites par la CI entrent dans le même commit que le code qui les justifie (étape 4, M30).

## Grandeurs instables

`INSTABLES` (dans `tests/outils_tests.R`) exclut de la comparaison aux références les grandeurs connues pour dépendre de la plateforme, chacune liée à une issue ; la liste est vide depuis la bascule sur la CI et doit le rester (ADR 0011, point 5). N'y ajoute une grandeur que si elle diffère **entre plateformes à code identique** (constat de la CI), jamais pour faire passer un test après une modification ; ouvre alors une issue et renvoie-y. `tests/comparer_references.R --tout` les inclut dans le tableau.
